# Private iOS HealthKit distribution for LifeOS

*Apple-source research checked 2026-10-20. “Free” below distinguishes **the price charged for the app** from the **Apple Developer Program membership fee**.*

## Decision

There is **no Apple-documented zero-cost native-signing route that stays valid indefinitely**. A free Xcode Personal Team install expires after seven days and must be rebuilt and reinstalled. For direct programmatic HealthKit writes, LifeOS needs a native iOS target: Apple requires the HealthKit capability/entitlement, purpose strings, and per-type user authorization before an app can write to the Health store ([Configuring HealthKit access](https://developer.apple.com/documentation/xcode/configuring-healthkit-access)).

A zero-cost *non-native* fallback exists: a user-created Apple Shortcut can use **Log Workout** or **Log Health Sample**. The existing PWA can invoke that saved shortcut with Apple’s `shortcuts://` URL scheme, but the shortcut—not LifeOS—must contain the Health logging action and its data mapping. This is suitable for deliberate one-user export, not a substitute for a native HealthKit bridge.

## Cost is not price

- **Developer-program cost:** Apple lists the Apple Developer Program at **US$99 per membership year** ([Membership Details](https://developer.apple.com/programs/whats-included/)). Membership supplies Certificates, Identifiers & Profiles and App Store distribution eligibility, and lists HealthKit among its capabilities.
- **App price:** App Store Connect pricing is separate. If the Paid Apps Agreement is not accepted, Apple says an app can only be offered **for free**; pricing is set before App Review ([Set a price](https://developer.apple.com/help/app-store-connect/manage-app-pricing/set-a-price/)). Therefore an App Store, unlisted, or custom app can have a zero customer price while its developer still pays the annual program fee.

### What a paid membership lapse means

For an Apple Developer Program membership, Apple documents that existing App Store apps still function but stop being available for download; the account can no longer submit apps or updates or access Certificates, Identifiers & Profiles ([Program Renewal](https://developer.apple.com/help/account/membership/renewal/)). That preserves an already-installed **App Store** build, but does not permit issuing fresh development or Ad Hoc profiles. Renewing restores free-app availability within 24 hours; paid apps also require accepting the Paid Applications Agreement, without resubmitting the app.

For profile-signed development and Ad Hoc apps, the profile’s own `ExpirationDate` is the immediate operational limit; use its actual date rather than assuming a fixed one-year duration ([TN3125](https://developer.apple.com/documentation/technotes/tn3125-inside-code-signing-provisioning-profiles)).

## Shortcuts: verified no-native-app alternative

Apple documents both **Log Health Sample** and **Log Workout** as Shortcuts share actions “used for logging data” ([About share actions in Shortcuts](https://support.apple.com/guide/shortcuts/apdaf74d75a5/ios)). Its user guide gives a concrete `Log Health Sample` example that logs weight ([About actions in complicated shortcuts](https://support.apple.com/guide/shortcuts/apd081d9d61f/ios)), and Apple’s Shortcuts release notes identify the `Log Workout` action and its duration input ([What’s new in Shortcuts](https://support.apple.com/en-us/101583)).

Apple also documents an invocation URL for an **already saved** shortcut:

```text
shortcuts://run-shortcut?name=[name]&input=[input]&text=[text]
```

The URL may be used from an app, a web browser, or the command line; its supported initial input is a text string or the clipboard ([Run a shortcut using a URL scheme](https://support.apple.com/guide/shortcuts/run-a-shortcut-from-a-url-apd624386f42/ios)). Therefore a LifeOS PWA can link to a preconfigured “Log LifeOS Workout” shortcut and supply URL-encoded text.

**Limits supported by the documentation:** this URL runs a named shortcut from the owner’s Shortcuts collection and passes only the documented text/clipboard input. Apple documents the Health-writing behavior as actions *inside* that shortcut; it does not document a Health-specific URL endpoint that accepts workout fields directly. The owner must create and maintain the shortcut, including parsing the input and configuring the Log Workout/Log Health Sample action. Treat it as a manual, user-owned export workflow—not as direct PWA access to HealthKit or a programmatic reconciliation channel.

## Practical recommendation

1. **For zero ongoing Apple-program cost:** retain the installable PWA and create one owner-controlled Shortcut containing `Log Workout` (or `Log Health Sample` where appropriate). Give the PWA an explicit “Export to Apple Health” link using the documented `shortcuts://run-shortcut` form. This can create Health records without shipping a native app, but its schema and user interaction are defined in Shortcuts.
2. **For direct, reliable LifeOS → HealthKit writes:** build a thin native iOS shell and enroll in the Apple Developer Program. For the strictly private single-device case, use Ad Hoc distribution and schedule profile renewal, new export, and reinstall before expiry. This avoids App Store review but is not install-forever.
3. **If avoiding periodic reinstallation matters more than strict secrecy:** submit the native app at a free price as an **unlisted** App Store app. It requires review and the $99/year membership, but it is not searchable and an installed App Store build continues to function even if membership later lapses; new downloads and updates do not. Use a private custom app only if Apple Business/School Manager distribution is actually available and desired.
